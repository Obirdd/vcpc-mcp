# 0.5.1-alpha.1：赛段验收与宇宙冠军研究接口

2026-11-02，Asia/Shanghai。基于四轮DSH原始账本（137场、1145TP）更新。冠军策略仍是待实测假设；本轮不恢复暂停目标、不开始真实比赛、不抽训练卡、不改DSH全局配置。

## 为什么更新

- 测试1实际末场是区域决赛，顶部已推进到世界总决赛，历史报告误判完成。
- 测试3的7次宇宙赛在顶部仍标世界总决赛；132次提交全部0AC；没有主动选题记录。
- 高评级训练收益明显收窄，≥3900的17次十连净−30；继续刷低评级收益不能保证突破5000。
- 测试4三个完整刷TP周期净增708、365、96；第四周期中止还剩90TP，不能把中途余额当作长期策略期望。
- 手写进度出现7次世决冠军写成8次、宇宙历史漏最后一场等错误。

## 已实现接口

| 更新 | 内容与使用方式 |
|---|---|
| 观察补充 | `competition.stage/source/title`来自赛前h1或FINAL STANDINGS标题；`identity.stage`保留顶部进度语义，兼容旧客户端 |
| 赛前情报 | `strategy_details`给出可见策略描述、失败处理规则、加成和选中状态；`competition.field_intel`保留公开情报原文，问号不补值 |
| 固定本场上下文 | owned-test的`run_context`从本场开赛begin派生，固定赛季、真实赛段、策略、Rating/TP，不随顶部推进而改变 |
| 指定赛段开赛 | `vcpc_start_contest(expected_stage=...)`在写入前和点击前均核对真实赛前标题；不一致或缺证据即不点击 |
| 决策窗口 | `vcpc_advance(stop_after_judgements=1)`在收取一次判题后返回；`stop_at_elapsed_minutes`按游戏时间返回；`pause_at_checkpoint=true`仅在无弹窗、仍在运行时发正常暂停动作 |
| 当前场报告 | `vcpc_get_run_report`从账本生成逐题已观察判题、连续失败、揭牌前准备度、事件选择、最终成绩与覆盖缺口 |
| 指定目标验收 | 同工具传`goal={stage,achievement}`，其中achievement为`completed/gold/champion`；只认`goal_verification.verified` |
| 档案统计 | `vcpc_get_profile_stats(limit=20)`去重汇总比赛、已核验冠军、训练实际收益和最近记录；不用手写progress累计值 |
| 赛后公开信息 | 仅final阶段增加`final.stage/heading/medal/review_text/standings_text`；赛中不输出未公开题目评级或隐藏结果 |
| 文本兼容 | EventRule增加可选`matching:"whitespace"`，仅归一化空白；保留金额、分钟、百分比、标点与选项顺序；重复或多规则歧义仍停下 |

### 决策窗口调用

```json
{
  "session_id": "使用当前连接句柄",
  "action_id": "使用新的稳定动作ID",
  "max_steps": 40,
  "timeout_ms": 20000,
  "stop_after_judgements": 1,
  "pause_at_checkpoint": true,
  "policy": {"policy_id": "当前档案保存的策略ID", "version": "当前版本"}
}
```

`0:30`表示30个游戏分钟，`1:00`表示60分钟。`stop_after_judgements`是本批次收取数量，不是整场累计数量。计数包含批次开始时已揭晓、随后由本批收取的判题。

检查`status`与`checkpoint.paused`。新事件或判题遮挡时只返回，不为暂停额外清除弹窗。达步数/时限、取消或失败也不会额外强行暂停。已暂停后先读取报告、按可见控件选题，再显式resume；普通advance不自动恢复、开赛、训练或选题。

### 宇宙第一名验收

```json
{
  "session_id": "当前连接句柄",
  "run_id": "本场实际run_id",
  "goal": {"stage": "可观测宇宙总决赛", "achievement": "champion"}
}
```

以下条件均成立才返回`goal_verification.verified=true`：

1. 本run开赛已确认，赛前主标题明确为目标赛段。
2. 同run最终结算标题为同一赛段，公开排名为#1且参赛数有效。
3. 提交、AC、各判题合计没有冲突。
4. 账本支持自然结束；提前结束或未知结束不能通过。
5. 复盘奖励已确认领取，或UI明确证实AK无复盘按钮；不存在未决写入。

金牌是另一验收目标，要求可见金牌标志，不能用第一名以外的排名猜奖牌线。旧账本没有新增标题字段时保留`unverified`，不以顶部或手写摘要自动回填。`natural_by_ledger`表示本MCP记录的自然结束证据，不是服务器随机种子或对未记录人工操作的证明。工具不会调用DSH目标完成接口；模型仍需保存截图与导出存档后再按用户目标收尾。

## 下一轮策略研究

详见工作区冲冠计划（本地研究资料，未随包发布）。主要改变是把高评级阶段从固定自动推进改为有决策窗口的选题实验，优先验证首次AC、准备度分布和失败次数是否改善，再追求足以超过该场第一名的过题数与罚时。

最终完整回归**137/137通过**，包含已确认、未发送与未知开赛/训练支出的区分。首次受限运行无法启动测试Chrome；在允许启动隔离测试浏览器后全量通过，未通过削弱测试断言来规避问题。另用新报告模块只读重算四轮历史137场/1145TP，收益与既有分析一致，宇宙132次揭牌覆盖完整；四份原账本哈希保持不变。日志位于工作区`data/vcpc/mcp-update-20261102/`。

为下一轮准备了执行提示词（本地研究资料，未随包发布）及33条历史签名的事件基线；只写到工作区，尚未启用到任何游戏档案或DSH模式。

真实网页只读核对了规则和赛前策略说明，并返回原大厅（Rating3015/TP41未变）；没有开赛。真实宇宙赛标题与比赛结果参考已有测试截图。本轮没有完成新真实比赛验收，也没有证明接口更新会赢得冠军；真实选择器与主动换题持续效果需在用户随后授权的DSH比赛中再核验。
